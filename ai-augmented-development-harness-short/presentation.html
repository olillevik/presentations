AI-Enhanced Software Development

developer + harness + AI

Harness engineering makes AI delivery more reliable by grounding it in existing developer workflows, controls, and operational feedback.

  • The point is not AI instead of the developer.
  • The practical question is how to make the combination reliable.
  • That is what I mean by harness engineering.
Harness model

What is the harness?

Context

prompts, skills, docs

Runtime and guardrails

repo, CI/CD, tickets, logs, metrics, runtime data, permissions

  • The harness is broader than tool integration.
  • Harness engineering is how we shape the AI's working environment: what it sees, how it acts, and how its output is checked.
  • Runtime and guardrails is the system-side environment: repo, CI/CD, logs, metrics, runtime data, and permissions.
  • Context harness is what we intentionally provide: prompts, skills, docs.
Current loop
build ->
test lint SAST dependency check code review
-> deploy to test -> verify deployment
  • This pipeline gives the AI evidence: test results, static checks, dependency findings, and deployment results.
  • That matters because the AI should not only see the source code. It should also see whether the change worked.
  • Code review and deployment verification are often manual and inconsistent.
  • The deterministic checks stay deterministic. Review remains part of the pipeline.
Enhanced loop
build ->
test lint SAST dependency check code review
-> deploy to test -> verify deployment
  • Strengthens secure delivery; does not replace controls.
  • Same harness, plus AI-enhanced code review and deployment verification.
  • More consistent PR review: CI step or standard review skill.
  • Story: auth bypass; it identified the known weakness and surfaced two similar places worth checking.
  • Qualitative review can be made operational: score, threshold, approval.
  • Deployment verification can include runtime review: logs, metrics, traces, and Kubernetes events, not just rollout success.
  • The point is not to remove humans, but to make these checks more systematic while keeping human judgement in the loop.
  • Security value: broader review coverage, better runtime follow-up, controlled access.

Enhanced loops

developer + harness + AI

  • This is still software engineering, not a separate operating model.
  • AI strengthens the loop by helping implement, review, and learn from runtime feedback.
  • That can make the overall engineering system more robust through broader review coverage and more systematic feedback.
  • The developer remains accountable.
