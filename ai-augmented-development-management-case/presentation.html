Lessons from the Trenches

This is a customer case from day-to-day software work. I still work close to the code. I will stick to what changed for us and what we learned.

I do not write code by hand anymore

Since November, my work has shifted from typing code to guiding and evaluating.

Opus 4.5 came out on the 24th of November. That model was suddenly much better. In combination with the tooling we already had, some of us stopped writing code by hand.

It is no longer just autocomplete

Then

Suggest the next line or the next function.

to

Now

Read context, plan work, edit files, run checks, iterate.

This is more than a typing helper. The tools can take a task, gather context, make changes, and check their own work.

Three things converging

Better models

Better models have made AI-generated code much more usable, even for fairly large changes.

Better tools

Agents can navigate repos, run tests, inspect CI, and work in loops.

Better usage

We've learned how to work with these tools effectively.

The model got better. The tools were already there. We also got better at using them. Those three things together mattered.

Context made the difference

The more relevant context the AI can access, the more useful it becomes.

  • Code - repositories, pull requests, code search
  • Work context - tickets, requirements, architecture notes
  • Delivery signals - build, test and deployment output, logs, monitoring, schemas
This is the main lesson. The result depends a lot on what the model can see. Tickets, code, CI, and logs make a big difference.

Augmented me

  • I decide what good looks like.
  • It does the legwork.
  • I review and own the outcome.
I still decide what good looks like. The AI does more of the legwork. I review and own the result.

Full autonomy was less useful than expected

Easy tasks were often faster directly from my own AI-assisted workflow. Hard tasks still needed close human involvement. That left less room in the middle than expected.

So the stronger case today is not "let the system run alone". It is "give skilled people much more leverage".

We tried more autonomy with Tinker. Easy tasks were faster from my own workflow. Hard tasks still needed me. That is why augmentation has been more useful so far.

The bottleneck moves

When coding speeds up, the next constraint becomes more visible.

review CI handoffs missing context approvals
Coding got faster. Then review, CI, handoffs, and missing context stood out more. The bottleneck moves.

What developers needed for this to work

  • Access - tools and relevant systems had to be reachable
  • Low friction - learning stalls when usage is buried in process
  • Room to experiment - skill grows through repeated practical use
This needed access, low friction, and room to experiment. It also needed sensible guardrails.

How to start safely

Start with broad read access

Code, tickets, CI, logs, and docs make AI much more useful before you grant it stronger permissions.

Be deliberate about write access

Use least privilege. Reading production signals is one thing. Changing production systems is another.

Match controls to risk

Sandboxing, approval steps, and compliance boundaries should reflect the system you are working in.

If a customer asks how to begin, this is the safe version. Start by letting AI see more, not do everything. Read access to the engineering system creates value quickly. Write access, permissions, and approvals should be introduced deliberately and matched to risk.

What made adoption work

  • Leadership signal - this was treated as important work, not a side hobby
  • Easy onboarding - people could get access and start using it without much friction
  • Champions and sharing - practical examples, reusable patterns, and active communities lowered the barrier
  • Clear boundaries - people moved faster when they knew what was allowed and what was not
This is the organizational lesson. Adoption did not come from one training session. It came from access, leadership backing, people sharing what worked, and clear boundaries that made experimentation feel safe.

Takeaways

Context creates leverage

Access, integrations, and context layering make AI useful.

Humans with AI beat either alone

Today, augmentation is more valuable than autonomy.

Improve the whole process

As coding gets faster, review, CI, context, and handoffs matter more.

These are the three things I would leave with. Context matters. Augmentation works better than autonomy today. The whole process matters, not just coding.
